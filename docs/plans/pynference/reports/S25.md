## Note per le sezioni successive
- Grafia QSA verificata dal dump (blk.3, S23-1): chiavi grezze dell'indexer
  senza norm/rope, scritte f16 nelle prime 128 righe della cache {256,262144};
  pooling = GET_ROWS con indice che indirizza le code incomplete alla RIGA 0
  della cache (leaf_108 = [0,1,2,3,0,0,0,0] a N=5), somma ÷compress sempre
  (anche per blocchi incompleti), RMSNorm(eps 1e-6)×γ k_norm, niente rope;
  la chiave del blocco incompleto viene scritta nella cache ogni passo
  (SET_ROWS su slot floor(N_old/cp)…ceil(N_new/cp)−1). Il query
  (rms+γ, rope NEOX alla posizione del token, n_rot 64) entra nel
  LIGHTNING_INDEXER grezzo: score = Σ_h relu(q_hᵀk)·(1/√(4·128))·…(idx_scale),
  −inf dove pos[4b+3] > pos[t]. La vista a 64 slot del dump (leaf_8) ripete
  l'ultima chiave scritta oltre l'ultimo slot pieno (indice clampato); in
  produzione i pool slot sono 512 (top_k 2048). In attention: K norm→rope,
  Q split [q256|gate256]→norm→rope, gate sigmoid moltiplicativo, C = wo.
- Per il passo 2 (decode): la cache pool va letta con indice clampato
  (GET_ROWS clamped), le chiavi grezze sono f16 in cache, e il blocco
  incompleto va riscalato e riscritto a ogni passo — il kernel di decode
  deve rifare l'ultimo blocco parziale, non solo aggiungere quelli pieni.
- Realizzazione passo 2 (commit 7cd95ae): prefill = `forward`torch
  device-agnostic eseguito su xpu (stesso codice su xpu, pattern S24);
  decode = `QSA.decode`: glue torch (cache pool incrementale con ripool
  da `old_n//compress` — le righe il cui GET_ROWS clampato cambia —,
  score, top-k, keep-set come lista fissa di celle int32 ≤ top_k+tail con
  −1 di padding) + UN kernel Triton `kernels.qsa_attn_decode`: flash-decode
  GQA con gather per id-cella dai cache cell-major [S,Hkv,D] (riga =
  cella·Hkv·D). Il keep-set limitato (~2054 celle) rende inutile lo
  split/combine di `attn_decode`. Su CPU la stessa lista diventa maschera
  additiva per `_attend`: la logica è testata sul PC senza GPU.
